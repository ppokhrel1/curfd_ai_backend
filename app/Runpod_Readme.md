# curfdai_ml API

RunPod Serverless worker for CAD generation workflows. The worker supports a multi-step flow:

1. Refine user prompt into structured requirements.
2. Generate SCAD/CAD output from requirements.
3. Upload the packaged output to Backblaze B2.

## Runtime

- Entry point: `app/main.py`
- Handler: `handler(job)`
- Platform: RunPod Serverless (`/run` and `/runsync`)

## Request Format

All requests must send an `input` object:

```json
{
  "input": {
    "action": "..."
  }
}
```

## Supported Actions

### 1) `process_requirements`

Converts a natural-language prompt into a structured requirements object and appends chat history.

Request:

```json
{
  "input": {
    "action": "process_requirements",
    "prompt": "Design a small quadcopter frame",
    "history": [
      {"role": "user", "content": "I need a lightweight drone"}
    ]
  }
}
```

Success response:

```json
{
  "status": "success",
  "requirements": {
    "model_type": "drone",
    "primary_function": "A small quadcopter frame for hobby use",
    "description_natural_language": "A compact central body with four arms equally spaced...",
    "standard_components": [
      {"name": "Flight controller", "search_term": "stack 20x20 mm"}
    ],
    "custom_description": "Use 3 mm thick arms, 160 mm motor-to-motor..."
  },
  "history": [
    {"role": "user", "content": "Design a small quadcopter frame"},
    {"role": "assistant", "content": "{\"model_type\":\"drone\",...}"}
  ]
}
```

Notes:

- `history` is optional (defaults to `[]`).
- `requirements` shape is generated by the model.

### 2) `generate_scad`

Generates model output from `requirements_json`, packages it, and uploads to B2.

Request:

```json
{
  "input": {
    "action": "generate_scad",
    "requirements_json": {
      "model_type": "drone",
      "primary_function": "A small quadcopter frame for hobby use",
      "description_natural_language": "A compact central body with four arms equally spaced...",
      "standard_components": [
        {"name": "Flight controller", "search_term": "stack 20x20 mm"}
      ],
      "custom_description": "Use 3 mm thick arms, 160 mm motor-to-motor..."
    }
  }
}
```

Success response:

```json
{
  "status": "success",
  "data": {
    "file_id": "b2_file_id",
    "filename": "assembly.zip",
    "download_url": "https://..."
  }
}
```

Validation error example:

```json
{
  "error": "No requirements_json provided"
}
```

### 3) `health`

Request:

```json
{
  "input": {
    "action": "health"
  }
}
```

Response:

```json
{
  "status": "healthy",
  "gpu": true,
  "service_initialized": true
}
```

## Error Format

Unhandled exceptions return:

```json
{
  "error": "<error message>"
}
```

## Environment Variables

These are required for full functionality:

- `DATABASE_URL`
- `SUPABASE_URL`
- `SUPABASE_KEY`
- `B2_KEY_ID`
- `B2_APPLICATION_KEY`
- `B2_BUCKET_NAME`
- `B2_BUCKET_ID`

Common optional overrides:

- `LLM_MODEL` (default: `/runpod-volume/qwen-3b-full`)
- `CODER_MODEL` (default: `/runpod-volume/qwen-coder`)
- `SDXL_MODEL` (default: `/runpod-volume/flux_schnell`)
- `HUNYUAN_LOCAL_PATH` (default: `/runpod-volume/hunyuan3d_2_mini`)
- `OUTPUT_DIR` (default: `/app/output`)

## Docker (GPU)

Build image:

```bash
docker build -t curfdai-ml .
```

Run locally with GPU and output mount:

```bash
docker run --rm --gpus all -p 8000:8000 \
  --env-file .env \
  -v "$(pwd)/output:/app/output" \
  curfdai-ml
```

The container starts RunPod serverless handler runtime:

```python
runpod.serverless.start({'handler': handler, 'return_aggregate_stream': True})
```
